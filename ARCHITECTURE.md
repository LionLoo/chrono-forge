# Architecture

## Product boundary

Chrono Forge has one authoritative deterministic simulation. React presents accessible controls and inspectors; PixiJS renders read-only projections; a module Web Worker owns mutable simulation state; Tauri/Rust owns native capabilities and durable SQLite persistence. Rendering, UI, wall-clock scheduling, and persistence never decide simulation outcomes.

## Runtime topology

```text
React UI ──commands──► typed worker protocol ──► simulation worker
   ▲                                              │
   │                 immutable deltas/events      │
   └──────────── Pixi renderer / inspectors ◄─────┘
   │                                              │
   └──── narrow Tauri IPC ◄──► Rust adapters ◄──► SQLite / OS
```

Source ownership converges toward:

- `src/simulation/`: pure authoritative state, systems, RNG, pathfinding, aggregation, save DTO migrations
- `src/protocol/`: versioned worker messages and persistence envelopes
- `src/workers/`: scheduler and transport only
- `src/rendering/`: Pixi scene graph and projection application
- `src/ui/`: React controls, inspectors, focus flows, settings, history
- `src/adapters/`: Tauri/browser boundaries, clocks, notifications, sound
- `src-tauri/`: typed commands, SQLite, atomic recovery, OS integration, packaging
- `tests/`: unit, invariant/property, determinism, integration, long-run, E2E, visual, benchmark scenarios

Imports flow inward: UI/rendering/adapters may depend on protocol and simulation read models; simulation imports none of them. CI enforces the boundary.

## Deterministic kernel

State advances only at integer logical ticks. Normal mode targets 10 authoritative ticks/second, rendering may run at 60 Hz, and projection publication is capped at 20 Hz. The scheduler uses elapsed wall time only to decide how many fixed ticks are due; it never changes tick results or skips authoritative ticks.

Forbidden in authoritative code: `Date.now`, `performance.now`, `Math.random`, locale-sensitive ordering, DOM/Tauri/Pixi/React imports, unordered asynchronous completion, and time-budgeted work. Use integer units for authoritative resources and measurements, total-order comparators, ascending stable IDs, fixed operation quotas, and quantization before any floating value becomes state.

The initial explicit system order is:

1. calendar and environment
2. needs and health
3. perception
4. personal and communal goal/utility decisions
5. movement
6. gathering, production, and construction
7. storage, transport, and trade
8. demographics, relationships, and institutions
9. research and culture
10. disasters and conflict
11. history events
12. aggregation and invariants

Commands receive worker-assigned sequence numbers and target ticks. Snapshots include RNG streams, queues, scheduler cursors, pending paths, aggregation state, next IDs, and acknowledged commands. Canonical hashes use sorted DTO arrays, never implicit `Map`/`Set` serialization.

## Randomness and decisions

A local, golden-vector-tested TypeScript port of xoshiro128** 1.1 supplies four-word `uint32` streams. Human seed strings normalize once to a displayed 128-bit seed. World generation, each global system, and each agent have independently derived streams so adding a farming draw does not perturb disasters or every citizen.

Agents use a documented utility/goal hybrid. Needs, opportunities, geography, personality, social state, knowledge, risk, plan cost, and bounded randomness produce candidates. A total order breaks ties. Occupations, construction, technology, settlement founding, and responses emerge from selected goals and available actions; the player does not assign routine work.

The M3 settlement slice advances six founders on deterministic 100-tick action pulses. Stable-ID records carry bounded needs, traits, skills, goals, plans, routes, knowledge, factual memories, relationships, activity-derived occupations, carried resources, and independently saved RNG streams. Agents gather from physical tiles, carry and deposit resources, select construction sites, and build, repair, expand, repurpose, abandon, or demolish shelters and storehouses. Pulse boundaries, fixed path quotas, total tie-breakers, and end-of-pulse invariant checks preserve arbitrary tick-partition equivalence.

M4 adds a deterministic 1,000-tick society pulse over the same settlement authority. A persisted calendar uses 100,000 ticks per civil year in normal worlds and 5,000 only in declared accelerated acceptance worlds. Society state owns stable person profiles, parent-linked households, cultural identities, groups, institutions, government, household inventories/credits/offers, production ledgers, inequality/stability, bounded biography references, and its own RNG stream and quotas. The communal survival stockpile remains the settlement safety reserve; declared recipes move conserved inputs into household exchange goods, and stable-price/time/ID ordering resolves offers. Births, deaths, inheritance, off-map migration, culture, and institutions never create a second settlement before M6.

M4.5 replaces the shallow M3/M4 social baseline with one canonical sparse interpersonal model. Stable bond IDs and canonical person-pair keys carry culturally appropriate roles/status, directional affinity/trust or equivalent state, closeness/commitment/grievance, lifecycle ticks, deterministic trend, bounded shared-event references, and isolated RNG state. The parent/guardian graph remains canonical genealogy; indexed queries derive sibling and practical extended-kin connections without materializing every relative pair. Direct family, active partner, household, and historically salient records are protected, while ordinary social edges and event references use declared deterministic caps and eviction/summary rules. No pulse enumerates every possible population pair.

Relationship opportunities run on fixed quotas in the demographics/relationships system and use total ordering over proximity, repeated interaction, shared work/events, traits, compatibility, culture, kinship, need, and deterministic RNG. Relationship state is an input to person-level utility and plans for cooperation, aid, caregiving, resources, household/partner/child decisions, migration, knowledge, politics/factions, conflict, reconciliation, crisis assistance, and inheritance; it biases autonomous decisions without directly scripting them. Household membership is versioned history, not a permanent birth assignment: formation, join, leave, split, merge, co-migration, separation, child arrival, and care changes are explicit typed events.

Child arrival must reference an eligible persistent relationship/family structure and a logged cultural rule. Important formations, transitions, conflict, reconciliation, separation, household change, and bereavement emit immutable source events used by biographies and relationship history. Worker read models expose bounded person relationship summaries and pageable details only on request; React provides deliberate keyboard-accessible family and relationship navigation outside the default calm focus surface. M5 crisis response, M6 cross-settlement movement/politics, and M8 aggregation must consume and conserve this same authority.

M5 adds one world-owned `DevelopmentState`, advanced after ordinary settlement and society work at each civil-year boundary. It contains a stable contextual knowledge graph, bounded modeled-condition pressures, active crises and retained outcomes, a closed queue of condition-changing interventions, independent persisted research and disaster RNG streams, and operation counts. The pure development pulse reads a fixed 256-tile terrain sample with binary sparse-depletion lookup plus immutable civilization context, evaluates fixed candidate quotas with total ordering, and returns ordered factual drafts and bounded conserved effects; it never mutates settlement, relationship, or tile authority itself. World orchestration applies those patches, synchronizes crisis health/death state, assigns stable event IDs, and then reuses the existing memory, biography, and sparse relationship attachment path. Crisis assistance and shared trauma update the already-authoritative M4.5 edge; harmed people and deterministic exposure drive caregiving, protection, and evacuation choices. Interventions may change weather/resource/organism/omen/artifact/protection/disaster/signal conditions, but cannot name a discovery, crisis, victim, helper, or outcome. Snapshot v5 persists this authority and migrates v4 saves to a no-retroactive-history baseline.

M6 adds one world-owned `CivilizationsState` after M5 development at each civil-year boundary. It owns globally unique settlement/civilization/residency/route/relation/conflict/ruin identities, fixed tile ownership and bounded ownership history, persisted settlement-development stages, independent persisted RNG, and stable-ID-sorted annual market and political resolution. Settlement development advances or regresses at most one adjacent `founding`/`village`/`town`/`city`/`advanced-city` stage per annual pulse, with hysteresis over actual population, stability, operational primary structures, active routes, owned territory, member communities, and contextual knowledge. The M3-M5 `CivilizationState` remains the global registry for detailed named people, structures, households, cultures, groups, institutions, genealogy, and sparse relationships, so cross-settlement movement never clones social authority or weakens M4.5 limits. The founding settlement keeps the detailed action-pulse reserve; additional communities own authoritative annual reserves and named-resident membership, and founding/market transfers conserve goods exactly once so no resource exists in both layers. Active routes rebalance actual shortages within fixed route capacity; disruption stops exchange. Secondary residents use camera-independent annual community production/consumption until M8 generalizes validated aggregation/deaggregation.

Annual M6 order is founding/residency, community economy, markets/routes, diplomacy, conflict/refugees, conquest/federation/fragmentation, ruins/territory history, settlement development, factual attachment, and invariants. A stage change consumes bounded annual work and emits one factual event; the saved stage points back to the latest observed transition. Every candidate set and mutation uses fixed quotas and total tie-breakers; no elapsed-time budget or population-wide relationship pair scan is allowed. Cross-settlement decisions query only indexed household/kin/salient-edge candidates and use `relationshipDecisionInfluence` beside material, scarcity, stability, and diplomatic utility, never as an outcome command. Conflict targets and political partners are utility-selected; conflict winners use conserved material strength; abandonment uses settlement pressure. Conquest/ruin must evacuate residents, close invalid routes, transfer or clear territory, and collapse a civilization that has no active member settlement. Historical entities remain retained and referenceable after conquest, federation, fragmentation, abandonment, or ruin. M5 knowledge stays one world-observed graph in M6; route/conflict evidence feeds future contextual development without duplicating knowledge authority. Snapshot v6 conservatively wraps v5 as one provenance-labelled settlement/civilization at the saved tick and creates no retroactive M6 history. Worker v9 exposes the stage and its tick/provenance beside bounded read-only settlements, civilizations, markets, diplomacy, conflicts, residencies, ruins, and space state; React provides deliberate keyboard-accessible inspection.

M9 adds one world-owned `SpaceState` after the M6 annual resolution. Immutable seed-generated bodies, civilization programs, ships, missions, orbits, due-tick travel and communication, colonies, interworld cargo, alien civilizations, and space relations stay separate from tile-bound terrestrial settlement authority. The pure space pulse reads a bounded context containing actual contextual knowledge, active civilization and settlement capacity, diplomacy, stored goods, and eligible unsalient resident IDs; it returns ordered patches and factual drafts that `World` applies exactly once. Advanced energy and planetary engineering create real program capacity before contextual spaceflight can launch. Travel and messages resolve by integer `(dueTick, id)` ordering, and isolated system/program/mission/contact RNG streams keep unrelated draws independent.

An off-world founding removes the exact ordinary resident IDs and cargo from M8/surface authority at departure; the mission owns them in flight and the colony owns them after arrival. Named or salient M4.5 lives never cross this aggregate seam implicitly. Off-world births use a disjoint saved allocator, while colony population, cargo, finite deposits, cultural divergence, and relations remain bounded and camera-independent. A program cannot cross from planetary engineering into spaceflight unless its civilization currently owns an active authoritative advanced city in addition to the existing knowledge, stability, institution, material, energy, engineering, and exchange gates. Snapshot v10 initializes a deterministic unreached system for v9 saves at the saved tick without synthesizing launches or contact. Snapshot v11 version-marks M10 procedural content and upgrades only exact `Body-N` celestial placeholders in v10 saves to deterministic seed-derived names; physical authority, RNG state, references, and history are preserved byte-for-byte otherwise. Snapshot v12 persists settlement stages; migration derives the highest stage supported at the saved world tick, marks migration provenance, and emits no retroactive transition. Snapshot v13 closes the player-visible event-kind catalogue and audits persisted description copy. Snapshot v14 binds person residence starts and ends to factual birth/death authority and household residence starts to known formation history. Migration repairs only the earlier timestamp direction emitted by the v13 stale-annual-tick defect, only within one saved civil year; forward-dated, active-after-death, overly stale, or inverted histories fail closed. The repair changes no event, RNG stream, resource, person, household, or other simulation authority. Older migration changes only display summaries and matching bounded memory or focus-recap copies when needed to replace a placeholder, reject generic wording, or identify typed participants; event IDs, kinds, ticks, references, amounts, RNG, and all other authority remain unchanged. Recap history prose is accepted for display only when its bounded copies still match a semantically valid retained active-slot event exactly; detached or inconsistent history retains session accounting and source IDs without presenting an unverified claim. One active snapshot is indexed once per archive refresh, and every history entry checks at most the twelve persisted recap IDs. Worker v9 carries stable bounded civilization/space projections and ordered deltas. React exposes the system only inside deliberate world inspection, and production advanced/space rendering is gated by real authority rather than presentation fixtures.

The locked detailed-person budget is 24 active elective edges, 24 archived relationship summaries, 16 significant shared-event references per edge, eight rows per detail page, 16 recent household-membership intervals plus one prefix summary, and eight new-candidate evaluations per person per civil year. Active partners are protected within the edge cap. Canonical parent/guardian-child records carry evolving directional emotional state in a separate O(population) family index; current-household membership is also linear, while emotionally salient sibling/extended-kin bonds use elective slots. Fixed retention tuples prioritize major events, then integer closeness/grievance, recency, and stable IDs; overflow becomes bounded category/tick summaries. These constants and total orders are authoritative versioned data, not runtime timing heuristics.

M4.5 v1 supports exactly two child/family policies: `pair-bond` and `communal-guardianship`. Both require living adults aged at least 18, valid settlement/household capacity and resources, a persisted cooldown, compatible selected family/care goals, and stable tie-breakers. Partner formation and pair-bond co-parent selection exclude parent/child and all ancestor/descendant, sibling/half-sibling, aunt-or-uncle/nibling, and first-cousin pairs. Pair-bond arrival additionally requires reciprocal active partner/long-term-partner state with bidirectional trust at least 50 and commitment at least 60. Communal guardianship requires the culture flag and one or two co-resident guardians; two guardians may be direct kin and otherwise need an existing partner or close-friend bond. Default cultures allow one committed partner; an explicit plural-partnership culture may allow at most two. Adoption/guardianship of an existing dependent selects only current household, direct kin, or salient caregiver/friend candidates and never creates a child or retroactive parentage.

World events use explicit entity kinds (`world`, `person`, `structure`, `household`, `culture`, `group`, or `institution`) plus stable IDs and an immutable bounded factual summary. Display surfaces quote that saved summary and source ID rather than reconstructing historical claims from mutable current state. The authoritative event archive remains canonical; Worker frames expose eight-row timeline pages, at most 256 recent events, and at most 16 biography references per person. Snapshot v3 migrates v2 by initializing society at the saved tick and preserving every old event; it does not synthesize births, institutions, or other retroactive history. Migration may begin between society boundaries, so the next pulse uses the next absolute 1,000-tick boundary rather than assuming the saved tick was aligned.

M4 acceptance can apply one explicit recorded `supply-shortage` input to a deterministic checkpoint. It conservatively removes communal and household goods, may damage one shelter, and then leaves mortality, migration, collapse, and recovery to normal pulses. This is scenario evidence for economic propagation, not an unrecorded ambient disaster or a substitute for M5's modeled crisis systems. Collapse recovery uses scarcity/stability hysteresis so it cannot oscillate at one threshold.

## World, pathfinding, and scale

Terrain is a chunked tile world; the initial chunk is 32×32 tiles. Dynamic entities use a deterministic uniform spatial grid. Local movement uses A* with fixed neighbor order and heap order `(f, h, nodeId)`. Shared goals can use reverse-Dijkstra flow fields; long routes use chunk portals. Cache keys include navigation revision and movement class, and incremental work consumes fixed node-expansion quotas.

The M1 development baseline is 96×64 tiles arranged as six 32×32-or-smaller chunks. M10.65 promotes the v1 default to one 256×192 authoritative homeworld arranged as 48 32×32 chunks; historical saves retain their persisted dimensions. Authoritative tile fields are dense typed arrays for elevation, water, temperature, moisture, biome, five resources, habitability, hazard, plants, and animals. Integer-only multi-scale lattice noise creates coherent regions; coordinate hashing supplies local resource detail. A central sanctuary guarantees a substantial connected habitable region without changing seed determinism. Initial history contains factual `world-generated` and `founders-arrived` events at tick 0. Civilization ownership and settlement growth expand within the shared surface; camera framing never expands, contracts, or otherwise changes authoritative geography.

Settlement action pulses coordinate only agents choosing work from the same source tile. Stable agent/action/tile preferences and an integer penalty on an already reserved `(source tile, action, target tile)` assignment spread co-located workers across viable resource targets without changing the underlying action utility. The reservation ledger is rebuilt deterministically in stable agent order for each pulse, includes only living agents with valid active plans, and never crosses source tiles. It therefore prevents identical founder routes caused by a globally shared best tile while preserving factual shared work when geography or construction offers only one real target. No camera state, wall clock, or nondeterministic entropy enters this choice.

The primary stage owns two read-only presentation modes with independent camera state. **Surface** consumes the existing terrestrial frame projection. **System** derives stable layout only from the bounded saved `SpaceState` projection: the homeworld, generated bodies, orbits, programs, spacecraft, missions, colonies, cargo and communication transit, discovered aliens, and relations. Stable IDs and saved distances determine total layout order and selection identity; animation and camera transforms are decorative. The system view never assigns authoritative tile coordinates to off-world state, reveals uncontacted alien authority, or synthesizes body terrain or events. Countries remain civilization/territory overlays on Surface rather than separate world authorities.

The version-2 frame projection copies biome, aggregate resource, habitability, and hazard arrays plus stable-ID-sorted packed agent and structure arrays, normalized structure progress/condition, and settlement totals before transfer. The main thread never receives authoritative arrays. Worker input is treated as untrusted structured-clone data: every request is validated and reconstructed before dispatch, malformed input becomes a typed fault, and an unsupported numeric protocol version takes precedence over version-specific field validation.

Camera distance affects rendering detail only. Authoritative LOD uses deterministic population/settlement tiers, historical importance, and scheduled cadence. Aggregation/deaggregation must conserve population, resources, historically salient relationships, genealogy, household membership/history, ownership, knowledge, and referenced events covered by invariants. M4.5 relationship work and storage are measured against people plus represented edges/index records, never the square of population.

M8 represents every live named Society person as protected detail and each settlement's remaining authoritative population as stable-ID anonymous residents. Anonymous provenance must match an active settlement's civilization, culture, and center tile exactly. Cohorts contain at most 1,000 residents; fixed schedules, a persisted member-promotion cursor, one transfer per World reconciliation, and bounded transfer/backlog telemetry prevent camera-dependent outcomes or sampling starvation. A disjoint persisted ordinary-resident allocator never reuses removed identities. Snapshot v9 persists this authority; v8 migration verifies the retired canonical payload, remaps ordinary identities, normalizes old household cohorts to settlement provenance, splits oversized cohorts with exact total conservation, and creates no history.

Live settlement movement uses the persisted path cache. A bounded coarse route plus one-chunk guard band narrows the first full-quota tile search. If that corridor does not cover the whole grid and cannot complete, the request persists a deterministic `direct-fallback` stage and its exact expansion offset; the next scheduled cache pulse spends one full tile quota on the direct grid. Thus hierarchical overhead cannot permanently reject a route the direct search could reach, while no pulse doubles expensive tile work. The derived total bound is at most two fixed tile-search quotas plus coarse nodes. Snapshot v9 persists deferred fallback authority; v8 rejects the unknown field. Terrain passability changes advance the saved revision and invalidate affected paths. Completed entries cap at 128; pending unique demand also caps at 128, repeats coalesce, saturated demand retries after the fixed 32-request settlement-pulse quota frees capacity, and oldest queued authority is never displaced by observation timing. Hot cache transitions use constant-cost structural guards and preserve already-canonical collection order; deep entry validation remains mandatory at world-pulse, persistence, canonical-DTO, and explicit invariant boundaries rather than repeating an O(cache) scan for every agent request.

## Worker protocol

The UI sends `initialize`, `load`, `queueCommand`, `setRunMode`, `advanceTicks`, `requestSave`, `requestFreshWorldSnapshot`, `requestFocusCheckpoint`, bounded timeline/relationship page requests, and `performOfflineCatchUp`. The worker returns `ready`, `commandAccepted`, `frameDelta`, `eventBatch`, bounded inspection pages, `saveSnapshot`, `focusCheckpoint`, `metrics`, and `fault`. `advanceTicks` is rejected above 1,000,000 ticks per request, every event-emission path is capped at the newest 256 records, and complete history is requested in bounded pages. Large projections use transferable buffers; messages are batched per frame, not per entity. Pixi stays on the main thread for v1. Shared memory and OffscreenCanvas require profiling evidence before adoption.

Worker protocol v11 emits the exact four-word world seed in each immutable full ready frame, then ordered base-tick-checked layer deltas, including settlement stage, change tick, and provenance. A delta cannot cross seed or dimension boundaries. Exact payload accounting counts every structured field and transferred buffer once; applying the complete delta stream must reconstruct the same canonical full projection, while stale or mismatched bases fail closed. The UI correlates every authoritative response to an outstanding request: only the exact initialization request may establish the first ready frame, concurrent loads complete FIFO, advance/offline deltas require matching pending IDs, and offline metrics cannot complete before their frame. Unsolicited, stale, or reordered authority faults before replacing the last valid projection. A synchronously rejected post removes its exact pending entry before retry so an unreachable request cannot leak or poison ordering. Only one ordinary advance may be outstanding. One separately typed phase-changing transition may queue behind it so Pause, Cancel, or completion crosses the Worker boundary without being swallowed by routine latency; equivalent or third work is rejected before it becomes accepted focus time. Every accepted advance retains its own fixed 10-second response deadline, and any unanswered request faults and terminates the Worker instead of growing an unbounded queue or hiding starvation behind partial progress. The focus-checkpoint request returns a canonical snapshot plus the bounded factual session moment, post-baseline event copies, and revisit target derived from that exact authoritative state; React never constructs or mutates review authority. The fresh-world request runs `createInitialWorld(seed, config)` inside the Worker and returns its canonical tick-zero snapshot without replacing the active world. Generation failure is request-scoped because it cannot invalidate the existing authority.

Offline progression is an explicit logged input containing elapsed milliseconds, configured rate, and policy version. It is clamped and simulated in deterministic coarse batches; unbounded real-time catch-up loops are forbidden.

## Persistence and recovery

Rust exposes only typed commands such as list/load/commit/delete slots, import/export, settings, focus history, and database checks. The WebView never receives a general SQL surface. SQLite lives in Tauri `AppLocalData` with WAL, `synchronous=FULL`, foreign keys, and a busy timeout. Command-bound focus state is parsed as the complete exact-key versioned shape, must satisfy the same lifecycle and integer tick/remainder rules as TypeScript, and must reserialize byte-for-byte canonically before a transaction begins. Session IDs cannot move between slots or regress accepted accounting; after completion or cancellation the entire stored session, factual recap, and review are immutable. Authoritative snapshots begin as canonical JSON envelopes with format, engine/content versions, seed, tick, checksum, and payload. Snapshot v3 persists the complete settlement and society graphs and validates lifecycle, ownership, parentage, household/culture/group/institution references, routes, plans, event sources, resources, RNG streams, and bounds during rehydration. v2 adds society at the saved tick without replaying a past; v0/v1 terrain-only saves found the six agents at the saved logical tick in constant time and record that founding event. Migration never retroactively simulates or invents unlogged history.

World lifecycle operations use one serialized UI queue. Every requested transition synchronously blocks focus actions and direct tick dispatch before its first await. Ordinary slot, save, export, settings, and lifecycle requests retain FIFO behavior and resolve against the final Worker-owned workspace. Reset cannot enter behind another world transition, then adds an exclusive synchronous barrier so neither its confirmed slot nor its same-turn durable outcome can race an archive or lifecycle mutation. New World and Duplicate Current World first commit a new immutable slot, then require the Worker to load that exact committed snapshot before React transfers active authority; only afterward is `activeSlotId` saved. A load failure leaves the original Worker world and preference active while retaining the safely inactive new slot. Reset World first retains the exact active snapshot, loads the Worker-created fresh snapshot, commits it as the next generation of the same slot, and restores the retained snapshot if that durable commit fails. Reset never writes another slot. If a reset receipt cannot be verified, its Worker rollback fails, or its committed generation cannot be synchronized with the archive UI, the shared operation queue and every focus/archive/settings write fail closed until restart; this prevents an ambiguous Worker from overwriting either possible durable head. A preference-write failure after a successful new-slot load is reported without pretending the already adopted Worker world is still the old slot. Random seeds are selected at the UI edge with Web Crypto, normalized to four `uint32` words, shown as four eight-hex groups, accepted in that exact reproducible format, and persisted as ordinary simulation input.

Canonical snapshot v4 persists bond identity/state/RNG, indexed genealogy and guardianship, household membership history, relationship event references, and immutable child-arrival eligibility evidence. The v3-to-v4 migration maps nonzero parent IDs to provenance-labelled genealogy with unknown start and neutral `migrated-unknown` family-bond state, opens current household intervals with unknown start, and maps only changed legacy affinity/trust or the stored M4 society pair to capped `legacy-contact` edges by copying stored integers. A global deterministic descending importance order greedily admits legacy edges only while both endpoints have capacity. Migration discards default 50/50 complete-graph contacts and infers no friendship, rivalry, partnership, estrangement, or event. Legacy contacts cannot satisfy lifecycle acceptance until a recorded v4 transition occurs. Validation rejects self/duplicate bonds, impossible ancestry cycles, invalid family/partner/household/event references, non-finite values, cap violations, and missing or mismatched child-arrival rule evidence before a migrated or loaded generation can become the slot head.

Saves are immutable generations. A transaction inserts generation `N+1`, verifies its SHA-256 readback, updates the slot head, and commits; pruning older generations happens separately after success. When focus is active, the same transaction stores the exact validated timer checkpoint, upserts history, and advances the head, so interruption cannot expose a world/timer mismatch. SQLite schema v6 also records that checkpoint's generation number plus a checksummed canonical session-authority copy. The bounded copy remains verifiable after the large world generation is pruned; history display uses it only when its slot and accounting identity still match the ordinary history row, while a missing or corrupt authority hides before/after claims without discarding harmless duration totals. Schema v8 defaults every generation to semantically unverified. The player performs one complete canonical TypeScript parse before commit; a current v14 snapshot enters its final parser directly, while older formats still traverse every conservative migration step. The native receipt's exact SHA-256 is verified with Web Crypto when available and the exact JavaScript implementation otherwise. After the durable write, a narrow native confirmation rereads the stored generation/checksum and marks it verified; only marked rows can establish the retention cutoff. Production creates the hidden local bundled validator WebView on demand for at most the first post-start save of each slot, reloads that requested generation through the same canonical gateway, and retires the validator only after its request-correlated result reaches the player. The complete create/validate/retire lifecycle is serialized process-wide so different slots cannot race the one fixed-label validator; rejection releases the queue for later best-effort baselines. The visible game WebView can send only a slot/generation/checksum request, Rust accepts the marking command only from the validator window label, and only the validator can request its own bounded retirement, so raw visible-WebView IPC cannot promote checksum-valid semantic failures into pruning authority. Semantic marking, verified retention, legacy corrupt-marker demotion, and unverified-tail retention share one immediate transaction. If any part fails, the marker and pruning roll back together while the already durable save remains successful because the post-write confirmation is best effort; this avoids duplicate writes, partial retention authority, and deletion of the last recoverable generation. A verified baseline remains protected beside the newest three unverified evidence rows; without any verified baseline, a fourth unverified write fails closed rather than deleting the only recovery evidence. Closing or externally destroying the player-facing window exits the entire process so no validator can remain orphaned. Loading is deliberately two-stage and paged: Rust scans at most one head-first/newest-first generation per native call, returns only a structurally verified candidate plus the exact scanned-generation cursor, and never materializes an unbounded fallback set or IPC payload. TypeScript requires the exact one-candidate envelope, binds every non-empty cursor to that candidate's generation, then validates the world, timer, references, dimensions, ranges, and checksum before requesting a strictly older page. Structurally invalid rows may produce an empty page with a decreasing cursor. Recovery performs at most eight such page validations: the durable steady-state envelope is six rows, two extra pages permit normalization of a pre-fix interrupted-prune archive, and anything deeper fails closed while retaining all untouched evidence. Native verified-retention repair likewise inspects at most eight marked rows, demotes checksum/structure-invalid legacy markers, and bounds their unverified tail in the same transaction. Export targets the exact semantically accepted generation. Full database backups use SQLite's backup API, never a raw copy of a live WAL database.

Database migrations live in Rust. Simulation payload migrations are pure one-version steps, validated after every step and written as a new generation. Unknown future versions are rejected without mutation. At least the prior two released payload versions remain readable throughout v1.x.

## Focus time

The focus timer is a versioned explicit-time state machine. Callers inject every epoch observation; backward wall-clock movement is clamped to the last accepted observation, and sleep-sized intervals account identically to partitioned checkpoints. Pause, cancel, optional breaks, and completion are explicit. Integer remainder accounting converts accepted focus milliseconds to simulation ticks without drift. A transition that issues simulation ticks crosses the Worker port before committing its accepted elapsed time locally; synchronous dispatch failure leaves both elapsed time and integer carry unchanged for one exact retry. Persisted state must pass exact-key semantic rehydration and agree with its typed session summary. The last active slot is persisted, session IDs use platform UUIDs, and completion effects occur only after the matching checkpoint is durable. Session recaps contain at most 12 sorted event IDs plus matching immutable tick/summary copies validated against the authoritative saved world and are displayed only for their own slot. Persisting the bounded display copy keeps a completed recap readable after the Worker's recent-event window advances; it is never regenerated from current state. Loading replaces, rather than merges, the UI event set.

## Sound and atmosphere

`src/adapters/soundscape.ts` owns project-original Web Audio synthesis at the presentation edge. Short cue envelopes cover direct focus actions, map selection, construction/progress, danger, discovery, completion, and restrained major events. Two-voice low-gain ambience has five factual scenes: founding, settlement growth, crisis, advanced city, and space. Scene selection reads only the current immutable Worker projection; event cues read only the Worker's latest newly recorded batch. Initialization and load batches are explicitly excluded, so opening a save never replays retained history. Camera, rendering detail, audio availability, and playback state cannot affect simulation authority, timing, persistence, or outcomes.

Audio is gesture-unlocked, optional, and failure-contained. The adapter creates no context for passive ambience before a deliberate audible action, resumes a suspended context best-effort, bounds composed gains, fades replaced ambience, and swallows unavailable-node/playback/cleanup faults. Master, ambience, effects, mute, and on/off settings persist in SQLite schema v7. Ambience is off by default; calm and reduced-effects settings suppress ambience and nonessential cues while quieter direct focus cues retain redundant visible states. Notifications remain an independent OS boundary. No cue is the only carrier of information.

## Rendering and accessibility

React owns semantics, focus order, keyboard controls, text scaling, inspectors, timelines, settings, and announcements. Pixi owns terrain/entities/effects and exposes selected objects through typed IDs. M7 inserts a pure versioned render-model adapter over immutable Worker frames. Selectable descriptors retain authoritative typed IDs; decorative roads, districts, farms, industry, infrastructure, weather, and era styling are deterministic bounded presentation anchored to recorded settlement/route/knowledge/crisis facts and never become simulation entities or history claims. A changed Worker frame prepares stable spatial buckets once; camera, overlay, selection, and reduced-effects updates query only guard-banded visible tiles and candidate descriptors. Stable ordered scene descriptors drive a semantic signature and committed SVG vocabulary baselines before Pixi applies separate dirty batches, pointer picking, and static selection cues. Camera/viewport/effects settings can only change presentation. Every visible structure also has text status/progress/condition and a non-color condition marker; overlays add text legends and redundant patterns. Reduced effects suppresses nonessential motion while retaining static nonspatial crisis boundaries and state cues. Map picking exists only for facts with an authoritative or explicitly documented presentation coordinate; nonspatial crises remain available through typed text inspection without inventing a tile. M4.5 adds optional person-to-family-to-relationship navigation with bounded summaries and on-demand history pages; no relationship surface is persistently opened or animated during calm focus mode.

M10.5 advances that boundary to render-model v2 without adding presentation authority. Stable IDs choose bounded silhouettes, skin and clothing palettes, building forms, roofs, settlement layouts, and terrain variants; factual action codes choose carried tools or work poses. Camera zoom chooses only `overview`, `district`, or `close` geometry and cannot change descriptor identity or simulation state. Above 512 visible agents, overview uses stable factual person/activity markers instead of detailed silhouettes. A whole-world overview with more than 1,536 visible people draws an evenly stable-ID-spaced 1,536-marker presentation sample and deterministically retains an otherwise omitted selected agent; authoritative projection, typed picking/selection, and district/close views still retain every person. Both thresholds change presentation cost only. Worker-projected space programs, bodies, spacecraft, missions, and colonies unlock code-native launch, orbital, craft, and dome landmarks. Their deterministic surface anchors are explicitly presentation coordinates tied to factual settlements and bodies, not claims that tile-bound civilization authority extends into orbit. Selection revisit framing centers a resolved factual tile with a pure camera transform; crises without a factual location expose their state through a whole-world boundary and text inspection but do not invent a marker or revisit coordinate. A host `ResizeObserver` invalidates visible-bucket planning whenever the map viewport changes; overview-following cameras refit to the new stage while deliberately panned, zoomed, or framed cameras remain under player control. Presentation refs accumulate rapid drag, wheel, and keyboard camera inputs before React commits, without entering Worker authority.

The release shell keeps the focus session hearth in the primary reading order beside the dominant world stage on wide layouts and before it on narrow layouts. The settlement chronicle, archive, settings, inspectors, and loading, empty, and fault surfaces retain native semantics and redundant text. CSS-only materials, contours, focus rings, responsive grids, and reduced-motion fallbacks keep the art direction local, deterministic, scalable from 100% through 200% text, and independent of GPU or sound availability.

Tauri keeps a strict CSP without `unsafe-eval`. PixiJS loads its statically generated `pixi.js/unsafe-eval` fallback before renderer initialization; despite the package entrypoint name, this removes runtime code generation and is required for WebView2 under the strict policy.

Native persistence defaults to Tauri's OS-resolved application-local-data directory. For isolated installed-artifact verification, `CHRONO_FORGE_PROFILE` may select one validated 1-64 character ASCII profile name below that same application root at `profiles/<name>`. The value cannot contain separators, traversal, whitespace, or an arbitrary path; invalid values fail startup closed. This native-only boundary never exposes a filesystem path or general file access to the WebView.

Installed persistence E2E assigns a fresh validated profile before launch and uses only two `desktop-e2e`-feature slot markers to inject an interrupted transaction and a corrupt newest checksum. Both branches are compiled out of production, and the production executable scan rejects either marker. The recovery phase closes the sole native window so the launcher must start a new process, then proves exact older-generation recovery through the rendered active world and raw typed IPC. After the launcher exits, the runner opens that exact profile database read-only and requires SQLite integrity, foreign-key integrity, and the exact cleaned archive shape; a failed application assertion or database check is fatal.

All runtime assets are bundled locally. Tauri uses a restrictive capability list and CSP; no account or remote content is required.

## Performance budgets

The release reference world targets 5,000 detailed agents plus 100,000 aggregate residents at 10 ticks/s, p95 tick under 50 ms, p99 under 100 ms, projection application p95 under 8 ms, projection payload under 4 MiB, and peak heap under 512 MiB. A 50 MiB save targets durable commit under one second and load/validation under two seconds on the documented reference machine. CI compares deterministic operation counts and median timing; a timing regression is blocking when it exceeds 25% and an absolute budget.

## Security and privacy

All core data is local. Tauri capabilities grant only needed IPC. Imports are size-limited, version/checksum validated, parsed as data, and never executed. Release workflows receive write permissions only in the release job. Signing secrets never enter PR workflows. A private GitHub release is not used as an anonymous updater endpoint and no reusable repository token is embedded in the app.
