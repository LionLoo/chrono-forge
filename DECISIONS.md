# Architecture decisions

Decisions are append-only. Reverse one by adding a superseding entry and migration plan.

| ID      | Decision                                                                                                                                                                    | Rationale and consequence                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ADR-001 | Windows 10/11 x64 is the supported v1.0 release platform.                                                                                                                   | It is the available native QA environment and permits an honestly verified installer. The Tauri/web architecture stays portable; other platforms require their own native gates before support is claimed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ADR-002 | Use React 19.2.8, Vite 8.2.1, PixiJS 8.19.0, Tauri 2.11, Node 24 LTS, and Rust 1.97.1 with exact pins and lockfiles.                                                        | Current stable, maintained components satisfy accessible UI, accelerated 2D, small native packaging, and testability. Vite 8 requires Node 20.19+/22.12+; Node 24 is current LTS. Pixi WebGL is used; WebGPU remains off until its production risk is justified.                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ADR-003 | Keep TypeScript at 6.0.3, not current 7.0.x.                                                                                                                                | TypeScript 7 currently lacks the stable programmatic API expected by lint/tooling, and typescript-eslint supports TypeScript below 6.1. Revisit when the ecosystem officially supports the new API.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ADR-004 | One pure TypeScript fixed-tick simulation runs in a dedicated module Worker.                                                                                                | It separates authority from UI/rendering, avoids frame-rate history changes, enables browser/Node determinism tests, and keeps v1 complexity below multi-worker shared-memory designs.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ADR-005 | Use an in-house data-oriented kernel, xoshiro128** streams, uniform/chunk grids, and deterministic A*/flow fields.                                                          | Stable iteration, save layout, aggregation, profiling, and complete tie-breakers matter more than generic ECS/pathfinding convenience. These core primitives need no runtime dependencies.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ADR-006 | React owns accessible UI; Pixi owns an imperative read-only world scene.                                                                                                    | Mirroring every entity into React would cause avoidable reconciliation cost. `@pixi/react`, OffscreenCanvas, WebGPU, and SharedArrayBuffer are excluded from v1 unless profiling proves necessity.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ADR-007 | Rust owns SQLite through narrow typed commands using bundled rusqlite.                                                                                                      | Browser storage depends on WebView profile/quota. General frontend SQL grants excessive authority. Rust can transact, checksum, back up, recover, and migrate saves consistently.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ADR-008 | Saves are immutable canonical JSON generations with checksums before any binary codec.                                                                                      | JSON is transparent and migration-friendly. Measured save budgets, not intuition, decide whether compression/binary encoding is later required.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ADR-009 | The simulation uses utility scoring plus explicit goal plans.                                                                                                               | Utility reacts to continuous needs and context; short plans handle multi-step gathering/construction/research. Deterministic candidate generation and tie-breaking prevent scripted universal progression.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ADR-010 | Authoritative simulation LOD never depends on camera position.                                                                                                              | Observing a different area must not change history. Rendering LOD may use the camera; simulation aggregation uses deterministic social/historical criteria and conserves key totals.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ADR-011 | Use Vitest/fast-check, Playwright, Rust tests, deterministic soaks, budgeted benchmarks, and add WebdriverIO Tauri service with the first native persistence flow.          | Each layer catches a different failure class. WebdriverIO's current dependency tree contains unresolved high-severity development-tool advisories, so it is not installed in M0; M2 must re-audit before adding its separate instrumented desktop build. Visual baselines run on one fixed OS/browser/font environment.                                                                                                                                                                                                                                                                                                                                                                                                           |
| ADR-012 | Ship manual private-release downloads in v1 unless an authenticated update host is separately authorized.                                                                   | Tauri updater signatures are mandatory and private GitHub release URLs are not anonymous. Embedding a reusable GitHub token would violate the security boundary.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ADR-013 | Generate one deterministic CycloneDX release SBOM from the npm lockfile and target-filtered Cargo metadata with a project-owned script.                                     | This covers both WebView and native dependency graphs without an unpinned release-time SBOM tool. The generator fails when runtime packages, Tauri, or dependency references are missing; the release publishes the validated JSON beside the installer and checksum.                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ADR-014 | Represent the M1 world as dense typed-array fields and transfer only copied versioned projections.                                                                          | Data-oriented storage gives stable ordering and compact snapshots without allocating per-tile objects. Renderer transfer cannot detach or mutate authority, and every request entering the worker is validated as untrusted structured-clone data.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ADR-015 | Keep Tauri's strict CSP and load PixiJS's static `pixi.js/unsafe-eval` fallback before renderer initialization.                                                             | WebView2 blocks Pixi's default runtime shader code generation. The counterintuitively named fallback replaces it with generated static functions; enabling the CSP `unsafe-eval` directive is unnecessary and forbidden.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ADR-016 | Enforce LF for repository text with `.gitattributes`, except Windows command scripts.                                                                                       | Windows checkout conversion made unchanged files fail the exact Prettier gate. Repository-owned line endings keep clean-clone validation reproducible while `.bat` and `.cmd` retain CRLF.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ADR-017 | Validate save recovery in two stages: native SHA-256 candidate ordering, then canonical TypeScript semantic migration/rehydration.                                          | Rust remains the durability authority without duplicating the full simulation schema. A checksum-valid but malformed or future-version head cannot block recovery: the UI tries immutable candidates head-first, accepts only a fully valid world, and exports that exact generation.                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ADR-018 | Store an optional validated focus checkpoint on each immutable world generation and commit its history/head atomically.                                                     | A separately updated timer can double-count or omit ticks after interruption or corrupt-head fallback. Exact-generation pairing makes recovery internally consistent; retention counts only complete recoverable pairs, while global focus history remains a separate reporting view.                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ADR-019 | Run native E2E through a feature-gated embedded WebdriverIO build and prove those capabilities absent from production.                                                      | The embedded provider gives Windows/macOS-capable real IPC and restart coverage without shipping a driver. A pinned one-line package patch bypasses an upstream EdgeDriver preflight that incorrectly runs for embedded sessions; frozen install, audits, and a production artifact scan guard the workaround.                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ADR-020 | Model M3 civilization state as stable-ID-sorted immutable records advanced by deterministic 100-tick action pulses, while publishing packed read-only Worker projections.   | Six founders retain explicit needs, traits, skills, goals, knowledge, bounded memories, relationships, occupations, logistics, structures, path demand, and saved xoshiro streams. Pulse batching preserves fixed-tick partition equivalence and bounded offline/long-run work. The Worker is the sole production authority; UI-thread shadow simulation is removed rather than expanded.                                                                                                                                                                                                                                                                                                                                         |
| ADR-021 | Found civilization at the saved tick when migrating a terrain-only v0/v1 world; never replay settlement history that the legacy save did not contain.                       | Constant-time founding prevents untrusted large ticks from causing unbounded migration and avoids structures, activities, RNG changes, or recaps without source events. A canonical `founders-arrived` event and matching memories establish the v2 history boundary.                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ADR-022 | Model M4 as one settlement with multiple households and cultures, a persisted civil calendar, household exchange beside communal reserves, and typed factual event records. | A normal civil year is 100,000 ticks, keeping 30-60 minute sessions incremental; the acceptance harness persists a 5,000-tick year for tractable multi-generation worlds. Off-map migration and co-located cultures preserve M6's multi-settlement boundary. Household inventories/credits and deterministic offers make exchange, scarcity, inequality, theft, and inheritance real rather than counters. Event entity kinds plus immutable summaries let biographies, timelines, memories, and recaps prove exactly what occurred. Snapshot v3 initializes new M4 state at the v2 save tick without retroactive societal events.                                                                                                |
| ADR-023 | Bound M4 Worker work at protocol and emission boundaries, and model acceptance scarcity as one recorded supply input followed only by ordinary autonomous pulses.           | Each `advanceTicks` request is capped at 1,000,000, recent event batches at 256, timeline reads at eight rows, residents at 64, and biography references at 16. The recorded shortage removes rather than creates goods; collapse/recovery uses hysteresis, and all later deaths, migrations, and recovery remain normal outcomes. This closes freeze/memory risks and demonstrates economic causality without prematurely implementing M5 disasters.                                                                                                                                                                                                                                                                             |
| ADR-024 | Insert release-blocking M4.5 before M5 and model interpersonal life as a sparse event-backed graph plus indexed genealogy and household history.                            | M4's parent IDs, static household assignments, generic affinity/trust, and single social bond do not satisfy persistent friendship, kinship, partnership, or family-life depth. M4.5 uses stable salient edges with bounded state/events and derived kin queries rather than an O(N²) complete graph. Relationship state must affect person-level decisions, births require recorded family structures, household changes are factual events, and optional inspectors expose evidence. Snapshot v4 migration may create only structurally certain current links, never invented past relationships; M5-M8 must consume and preserve this authority.                                                                               |
| ADR-025 | Bound each detailed person's elective relationship state to 24 active and 24 archived edges, with fixed event/history/page/candidate quotas and deterministic retention.    | Parent/guardian-child bonds carry evolving emotional state in a separate O(population) genealogy index; current households are also linear, while emotionally salient sibling/kin bonds use elective slots. Edges keep 16 significant event IDs, detail pages show eight rows, household history keeps 16 intervals plus a prefix summary, and candidate formation evaluates at most eight new pairs per person-year from bounded indexes. Major-event/strength/recency/stable-ID tuples decide overflow, giving deterministic evidence and an M8-compatible O(people + represented edges) path.                                                                                                                                  |
| ADR-026 | Ship `pair-bond` and `communal-guardianship` as the finite M4.5 family policies and migrate v3 social data without inferring unrecorded relationship meaning.               | Pair-bond child arrival requires reciprocal committed partnership, thresholds, goals, household capacity/resources, cooldown, and close-kin exclusion. Communal guardianship requires an explicit culture rule and one or two related/partnered/close-friend co-resident caregivers. Existing dependents may gain guardians only from bounded factual candidates. V3 parentage and household membership retain provenance with unknown starts; changed legacy counters may become capped untyped contacts, while default 50/50 edges and all inferred romance/friendship/history are excluded.                                                                                                                                    |
| ADR-027 | Persist child-arrival eligibility as immutable structured evidence on both the arrival record and its typed world event, cross-validating semantic source identity.         | A historical birth must remain valid after its parents' relationship later changes, while a newly recorded birth must prove the exact current policy, household, guardians, pair-bond kind, bidirectional thresholds, and deterministic selection score. Same-tick pending records are checked against live authority; saved worlds require a nonzero eligibility event with exactly matching structured evidence. Event consumers match stable semantic kind/source fields rather than display-summary wording, so factual provenance survives copy changes without accepting unrelated events.                                                                                                                                  |
| ADR-028 | Own M5 knowledge, modeled pressures, crises, and queued interventions in one world-level deterministic development state advanced once per civil year.                      | One authority avoids splitting technology and disaster truth across society, settlement, and UI. Separate persisted research and disaster RNG streams prevent a technology draw from moving meteor timing. A fixed 256-tile sample uses binary lookup into sparse depletion, and fixed event/crisis/response quotas bound work without dropping factual events. Crisis effects synchronize agent/society life state immediately; harmed or exposed people enter M4.5 relationship-ranked care, protection, and evacuation. Closed typed interventions alter persisted conditions only, never an exact outcome. Snapshot v5 initializes this authority conservatively for v4 saves without replaying history.                      |
| ADR-029 | Add one world-owned bounded `CivilizationsState` with globally unique identities while retaining one global detailed people/relationship registry.                          | Duplicating the old single-settlement object would collide IDs, double-consume terrain, break factual references, and strand M4.5 bonds inside local societies. M6 therefore partitions named residents and community reserves through stable settlement records, keeps the founding settlement as the detailed M3-M5 logistics authority, and models additional communities on deterministic annual pulses until M8 generalizes aggregation. The layer owns routes, diplomacy, conflicts, territory history, federation/fragmentation, and ruins; it runs after M5, uses fixed quotas and relationship-indexed utility, has no direct player outcome commands, and migrates v5 to one no-history baseline in snapshot/Worker v6. |
| ADR-030 | Resolve M6 markets and geopolitics through conserved state and explicit utility, with strict succession invariants.                                                         | A route is not a market unless it moves existing goods, and a seed/year switch is not an autonomous political outcome. Active routes therefore transfer bounded shortages without creating resources; relationship state contributes to real political/conflict target selection; material strength resolves wars; stability, reserves, diplomacy, scarcity, and profile supply contextual pressures. Conquest or ruin cannot strand active residents, routes, territory, or a living settlement-less civilization. Controlled counterfactual tests and four semantic long worlds precede canonical hash renewal.                                                                                                                 |
| ADR-031 | Run deterministic long simulations serially outside coverage instrumentation, while requiring them in both hosted and full local gates.                                     | Coverage made CPU-heavy horizons exceed clocks on the two-core Linux runner even though completed assertions passed. The covered suite retains all thresholds; every long assertion then runs once with one worker and no file parallelism. Quoted exclusion prevents POSIX shell expansion, and both `ci:web` and `npm run ci` invoke the long catalogue explicitly so the optimization cannot weaken evidence.                                                                                                                                                                                                                                                                                                                  |
